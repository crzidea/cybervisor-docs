# cybervisor-docs

Static documentation site for [cybervisor](https://github.com/crzidea/cybervisor), built with [VitePress](https://vitepress.dev) and deployed to [Cloudflare Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/).

## Prerequisites

- Node.js 18+ and npm
- For local documentation edits, the `cybervisor` repository checked out at `../cybervisor/` (as in the cybervisor-workspace layout)

## Quick Start

```bash
# 1. Install dependencies
npm install

# 2. Sync documentation from the canonical source
npm run sync

# 3. Start local dev server
npm run dev

# 4. Build static site
npm run build

# 5. Preview built site locally
npm run preview
```

## Documentation Source

The canonical documentation source is `../cybervisor/docs/`. **Never edit files inside `cybervisor-docs/docs/` directly.** Always edit documentation in the source directory and re-run `npm run sync` to update the site.

The generated `docs/` snapshot is committed so isolated Cloudflare builds do not need to clone the sibling repository. When `../cybervisor/docs/` is available, `npm run sync` refreshes the snapshot before a build. When it is unavailable, the sync command preserves and builds the committed snapshot.

When you add or rename pages under `../cybervisor/docs/`, update the sidebar and top navigation in `.vitepress/config.mjs` so new pages appear in the site menu. Search uses VitePress local search only (no external search service).

## Scripts

| Command | Description |
|---------|-------------|
| `npm run sync` | Refresh `docs/` from `../cybervisor/docs/` when available, removing stale files and rewriting source-relative links; otherwise preserve the committed snapshot |
| `npm run dev` | Start VitePress dev server with hot reload (run `npm run sync` first after clone or source doc changes) |
| `npm run build` | Sync docs and build the static site to `.vitepress/dist/` |
| `npm run preview` | Preview the built static site locally |
| `npm run deploy` | Build and deploy to Cloudflare Workers |
| `npm run wrangler:dev` | Run Wrangler local dev server against built assets (run `npm run build` first) |

## Link Rewriting

The sync script automatically handles links that escape the docs tree:

- `../README.md` link references are converted to the cybervisor GitHub repository URL.
- All internal `.md` links are converted to VitePress `.html` paths.

## Cloudflare Workers Deployment

### Prerequisites

- A Cloudflare account with Workers enabled
- A Cloudflare API token with Workers deployment permissions (`wrangler login` or set `CLOUDFLARE_API_TOKEN`)
- Wrangler CLI (installed automatically as a dev dependency)

### Deploy

```bash
npm run deploy
```

### Production Route: `docs.cybervisor.ai`

The Wrangler configuration includes a commented-out route for `docs.cybervisor.ai`. This route is **not active** until you:

1. Confirm DNS and Cloudflare zone ownership for `cybervisor.ai`.
2. Uncomment the `[[routes]]` section in `wrangler.toml`.
3. Run `npm run deploy`.

To customize the route before deployment, edit `wrangler.toml`.

## Architecture

```
cybervisor/docs/          <- Canonical documentation source (edit here)
cybervisor-docs/docs/     <- Tracked snapshot generated by npm run sync
cybervisor-docs/.vitepress/config.mjs  <- VitePress config (tracked)
cybervisor-docs/.vitepress/theme/      <- VitePress theme (tracked)
cybervisor-docs/scripts/sync-docs.js  <- Sync and link-rewrite script
```

The VitePress site reads from `docs/` (configured via `srcDir`), which is generated by the sync script. The build produces static HTML assets in `.vitepress/dist/`, which Wrangler serves as a Cloudflare Worker.

Static assets in `public/` (e.g., `favicon.svg`) are tracked in git and copied into `docs/public/` by the sync script so that VitePress includes them in the build output.
